# Agent Latency Lab — VS Code Extension

Ships the existing Lab UI (trace waterfall, fork/join critical-path detection,
what-if optimizations, cost/RAG panel) inside a VS Code Webview, with no
changes to the standalone web app's behavior.

## What works in v0.1 (ship "A" — companion viewer)

- **Agent Latency Lab: Open** — opens the full Lab UI. Simulated-workload mode
  and "Paste your trace" both work exactly as they do in the browser, since
  neither depends on a network call.
- **Agent Latency Lab: Analyze Selected Trace** — right-click a trace block in
  any editor (or the Command Palette with a selection active) and it opens
  pre-loaded into the analyzer.
- **Agent Latency Lab: Analyze Trace from Clipboard** — same, from clipboard
  contents. Handy right after your instrumented server logs a paste-ready
  block to the terminal.

**What's intentionally inert here:** the live alert feed (which polls
`/debug/alerts` on a running server) has no server to reach inside a webview
and fails silently by design — it just doesn't render, exactly like the
standalone app when no server is running. No code changes were needed for
that; it already degrades gracefully. Wiring the webview to a *real* running
`npm run server` instance (via a workspace setting for the base URL, proxied
through the extension host so the webview's strict CSP doesn't need
`connect-src` opened up) is the natural v0.2 — deliberately out of scope here
to ship the core viewer first.

## Build & run locally

```bash
# from vscode-extension/
./build.sh                 # builds the Lab UI, stages it into media/, compiles the extension
```

Then in VS Code: open this `vscode-extension/` folder, press **F5** (Run →
Start Debugging) — this launches an Extension Development Host window with
the extension active. Run **Agent Latency Lab: Open** from the Command
Palette (`Cmd/Ctrl+Shift+P`).

## Package as a `.vsix` (installable, shareable)

```bash
npm install
./build.sh
npm run package     # → agent-latency-lab-0.1.0.vsix
```

Install the result with **Extensions view → "…" → Install from VSIX…**, or
`code --install-extension agent-latency-lab-0.1.0.vsix`.

## How the Webview bridge works

`src/extension.ts` reads the built `media/index.html`, rewrites its absolute
`/assets/...` script reference to a `webview.asWebviewUri(...)`-safe path,
and injects a strict Content-Security-Policy: scripts only run with a
per-load nonce, styles/fonts are scoped to what the app actually needs
(Google Fonts, inline `<style>` from the component), and `connect-src 'none'`
— the webview cannot make network requests at all in this version, by design.

When a command opens the Lab with a trace (selection or clipboard), the
extension host posts `{ type: "loadTrace", trace }` via
`webview.postMessage`; a small bridge script in the injected HTML re-dispatches
that as a `window` `CustomEvent`, which `AgentLatencyLab.jsx` listens for and
uses to populate "Paste your trace" mode. This is the only extension-specific
code path added to the React component — everything else is the same bundle
that ships as the standalone web app.
